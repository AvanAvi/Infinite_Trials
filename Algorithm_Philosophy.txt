Algorithm Philosophy: Partition-Based Encryption System

The algorithm operates on the principle that every character in a password can be mapped to a unique partition value, creating a mathematical fingerprint. This transforms traditional string-based password verification into a number-theoretic problem - though, as detailed in docs/ANALYSIS.md, summing those values is order-blind and many-to-one, so this is not a cryptographically secure construction.

The system implements multiple decryption strategies: backtracking for systematic exploration and meet-in-the-middle for complexity reduction from O(c^n) to O(c^(n/2)), with a hybrid approach planned but not yet implemented. Backtracking and meet-in-the-middle both enumerate character *multisets*, not ordered strings, since the sum can't distinguish order. This diversity is about performance trade-offs across problem sizes, not security - decryption returns one of many valid candidates, not necessarily the original password.

An earlier version of this repo included a partition-inversion tool (legacy/InvPart.c) built around a similar dynamic-programming idea, but it computed the wrong thing entirely (see its header comment for the details) and had a data race in its OpenMP-parallelized loop. The corrected version (Version2/src/inverse_partition.cpp) estimates n via the Hardy-Ramanujan asymptotic inversion, then confirms it exactly via Euler's pentagonal number recurrence, computed serially with no race.

For a password P = p₁p₂...pₙ, the encrypted value is Z = C + Σ partition_value(pᵢ) - a plain sum with no per-position weighting. No `position_weight(i)` term exists in any implementation, despite an earlier version of this document describing one. Decryption means finding character combinations whose partition values sum to K = Z - C, and that is not computationally prohibitive - see docs/ANALYSIS.md for exact counts of how many unrelated passwords share the same K at realistic password lengths.

The architecture emphasizes modularity through the strategy pattern, robust error handling with input validation, and comprehensive performance monitoring. This project demonstrates an intersection of theoretical mathematics and practical computation - it does not demonstrate effective cryptography, and shouldn't be treated as one.

On a personal note, the genesis of this algorithm came from watching "The Man Who Knew Infinity" while taking a cryptography class. I found myself wondering about the intersection of partition theory and practical cryptography, thinking simply "why not?" – because innovation is always about "why not," it is never about "why," at least this is what I believe.
